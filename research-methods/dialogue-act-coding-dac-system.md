# Dialogue Act Coding (DAC) system

> **Research Method** · [All research methods](index.md)
> **Evidence** · 2 claims (1 for, 1 mixed) · 1 study (1 design), `q3` · 0 of 1 report an effect size · 2 claims rest on one study

## Description
The DAC system identifies "dialogue acts", the communicative function of each utterance typed during online collaboration, building on the Verbal Observation System and discourse-analysis research. Its core assumption is that language users "signal the intended meaning and interpretation of their utterances to their discourse partners by means of explicit 'discourse markers'". It distinguishes five main communicative functions: "(1) Argumentative..., (2) Responsive..., (3) Elicitative..., (4) Informative..., and (5) Imperative (commands)", specifying "a total of 29 different dialogue acts". The system was used in CSCL studies of history and language arts inquiry tasks.

# Use a default catch-all code (InfStm?) to flag uncodable messages for manual checking

> **Strategy** · [All strategies](index.md)

## Description
When the DAC filter finds no discourse marker in a message, it assigns the InfStm? code as a default catch-all, marking the message for manual checking rather than risking a wrong automatic code. The article states "If the system does not find a discourse marker in a message, the message is coded by the label InfStm? as a default catch-all." ## Design Implications

### Context
#### Requirements
- A researcher must review and manually code the flagged InfStm? messages after automatic coding
#### Constraints
- The catch-all does not guarantee the DAC filter makes no other mistakes; disagreements not flagged as InfStm? remain unnoticed unless the protocol is checked
