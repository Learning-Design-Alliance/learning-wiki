## Evidence

### dos Santos 2014

dos Santos, R. P. (2014). Second Life as a Platform for Physics Simulations and Microworlds: An Evaluation. Originally published 2012. [doi:10.48550/arXiv.1405.6703](https://doi.org/10.48550/arXiv.1405.6703)

`q1 · i?` · `design · r2`

Evaluation of the ease-of-use, stability and portability criterion: the computational load of SL's server grid "leads to undesirable b ut understandable system instability and occasional falls", while client software remains small and portable.

> "The computational effort exerted  by SL grid of computers leads to undesirable b ut understandable system instability and occasional falls."

### dos Santos 2014 (2)

dos Santos, R. P. (2014). Second Life as a Platform for Physics Simulations and Microworlds: An Evaluation. Originally published 2012. [doi:10.48550/arXiv.1405.6703](https://doi.org/10.48550/arXiv.1405.6703)

`q1 · i?` · `design · r1`

The same evaluation reports "a high learning curve exists for new users", so any proposal of using SL for teaching must set aside several hours for students to become familiar with basic tasks such as walking and manipulating objects.

> "Most users agree that a high learning curve exists for new users (Sanchez, 2009), which means that any proposal of using of SL for teaching has to set aside several hours, just to have the students become familiar with basic tasks"

### dos Santos 2014 (3)

dos Santos, R. P. (2014). Second Life as a Platform for Physics Simulations and Microworlds: An Evaluation. Originally published 2012. [doi:10.48550/arXiv.1405.6703](https://doi.org/10.48550/arXiv.1405.6703)

`q1 · i?` · `design · r1`

On portability the evaluation notes that, unlike platforms such as AnyLogic, "the simulation itself cannot be exported as Java applets and be run remotely in a web browser".

> "Unfortunately, however, the simulation itself cannot be exported as Java applets and be run remotely in a web browser as allowed by other platforms, e.g. AnyLogic (Rodrigues, 2008)."
