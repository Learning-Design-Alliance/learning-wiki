# The permission pattern, where tool actions await tutor approval, addresses cases where preventing student action is the appropriate instructional response

## Subclaims
`q2 i?` The permission pattern addresses cases where the tutor must prevent rather than comment on student actions, though it violates the principle that tools need no tutoring consideration. [→ Ritter 2016](#ritter-2016)

## Evidence

### Ritter 2016

Ritter, S. (2016). Plug-in Tutor Agents: Still Pluggin'. International Journal of Artificial Intelligence in Education, 26, 405–415. https://doi.org/10.1007/s40593-015-0062-z

`q2 · i?` · `theoretical · r2`

The author describes the permission pattern as a later development addressing the limitation of the commentary pattern for irreversible actions, noting it violates the tool-independence principle but is reasonable when building purpose-built tools.

> "we later considered a Bpermission pattern,^ in which the tool communicates the user's desire to carry out an action (closing a window or changing the value of a cell), but the effects of that action await approval from the tutor."
