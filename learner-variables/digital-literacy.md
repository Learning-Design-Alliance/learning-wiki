# Digital Literacy

> **Evidence** · 15 claims (12 for, 1 mixed, 2 against) · 17 studies (4 causal, 4 review, 4 associational, 2 qualitative, 2 design, 1 quant-synthesis), `q1`–`q4` · 3 of 17 report an effect size · 13 claims rest on one study

## Description
Whether a learner can *operate* the interface — distinct from [access](access.md), which is whether they can load it at all. It covers navigation, file handling, knowing what is clickable, and the confidence to explore without fear of breaking something. Every course here is delivered digitally, so this is never out of scope, and it is the dimension most often assumed away: a designer fluent in the interface cannot see it.

## Implications

### Context
- Decides whether an interaction needs a walkthrough before it needs content, and how much of the UI can be assumed.
- Interacts with cognitive load: an unfamiliar interface consumes the working memory the task needed [~M].
- Not age-determined. Fluency with consumer apps does not transfer to file systems, forms, or academic tools.

### Target Learners
- Adult and returning learners, for whom this is the dimension most likely to be underestimated.
- Anyone meeting a genre of interaction for the first time — a simulation, a code editor, an annotation tool.

### Target Learning Objectives
- Gates every other outcome in a digital course: a learner who cannot operate the tool produces no evidence of anything else.
- Affects measured performance without affecting the underlying competence, so it is a validity threat as much as a learning one.

- Affect regulation — fear of breaking something suppresses the exploration that builds fluency.
