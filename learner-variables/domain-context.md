# Domain Context

> **Evidence** · 25 claims (23 for, 2 mixed) · 29 studies (11 qualitative, 6 review, 4 causal, 4 design, 3 quant-synthesis, 1 theoretical), `q1`–`q4` · 3 of 29 report an effect size · 22 claims rest on one study

## Description
The sector, role or setting a scenario must be placed in before a learner recognises it as theirs. This is the course-specific dimension: what counts as a recognisable case differs by subject in a way the other dimensions do not. It changes who appears in a scenario and what a task is *about*, not how hard it is — and it is the dimension most likely to be filled with the designer's own context by default.

## Implications

### Context
- Decides the setting a scenario is placed in, and therefore whether it reads as relevant or as somebody else's problem.
- Authenticity is a means, not an end: a realistic case that carries no transferable structure teaches the case.
- A domain dimension nothing depends on is decoration — it should name the goals or elements it bears on.

### Target Learners
- Learners with existing occupational or community context, for whom a mismatched setting is a barrier rather than a neutral wrapper.
- Learners with none, for whom the context must be built before it can be used.

### Target Learning Objectives
- Bears directly on transfer, which depends on how the original was encoded.
- Affects engagement and perceived relevance independently of any effect on learning.

## Related Learner Variables
- Prior knowledge — the domain-specific dimension it is most often confused with: this is setting, that is knowledge.
- Belonging — a scenario set somewhere a learner is not represented carries a message beyond its content.
- Motivation — recognisable context is one of the more reliable routes to perceived relevance.
