Analyze the Project¶

Strategy · All strategies Evidence · 2 claims (2 for) · 5 studies (3 review, 2 causal), q2–q3 · 0 of 5 report an effect size

Description¶

Before launching a project, teachers analyze it through the lens of English Language Learners (ELLs) by asking: What language skills will students need? What vocabulary instruction might they need? What speaking and listening skills should be scaffolded? What functions of language (arguing, explaining, sequencing, persuading) does each task demand? This analysis occurs before the project launches, so language support is designed into the project rather than retrofitted when students struggle.

Design Implications¶

Project-based learning embeds content learning in complex, language-rich tasks, which raises the language demands on ELLs precisely when cognitive demands are also high. Analyzing the project in advance lets teachers reduce extraneous language load while preserving the linguistic challenge worth learning Chunking reduces working memory load. [+S]. It converts implicit language expectations into teachable targets, aligning with the principle that academic language must be explicitly planned for, not absorbed incidentally Accessible vocabulary and syntax improve comprehension for language learners. [+M].

Context¶

Requirements¶

  • Understanding of second-language acquisition and the proficiency levels of the ELLs in the class
  • A detailed project plan (driving question, milestones, final product) complete enough to audit for language demands
  • Time allocated for analysis before launch, and resources for planned language support (glossaries, sentence frames, models)

Constraints¶

  • Requires extra design time and expertise; teachers without language-development training may misidentify which language functions matter most [-W]
  • Over-scaffolding identified demands can strip tasks of the productive struggle that drives language growth [~M] — supports should be planned but faded as proficiency develops
  • Analysis based on generic ELL categories rather than individual learners' proficiency data produces supports that miss actual needs [-W]

Implementation Variability¶

  • Lightweight version: a 30-minute audit of the final product and one key milestone for vocabulary and discourse functions
  • Deep version: task-by-task language mapping co-planned with an ESL/bilingual specialist, with differentiated supports per proficiency level
  • Student-involved version: analyzing a past project's language demands with students as an activation activity

Target Learners¶

  • ELLs at intermediate proficiency who have conversational fluency but not yet academic language — the analysis targets the academic-language gap [+M]
  • Newcomers, when paired with substantial scaffolds and first-language supports [~W]
  • The strategy also benefits other students with limited academic language, including many native speakers, making it a universal-design move rather than a targeted one [+W]

Target Learning Goals¶

  • Academic language development: discipline-specific vocabulary, syntax, and discourse functions
  • Access and equity goals: enabling full participation in collaborative project work rather than peripheral roles
  • Speaking and listening objectives embedded in project milestones (presentations, critiques, interviews)

Instructions¶

  1. Map the project's language demands: list the vocabulary, text types, and language functions (describe, justify, summarize) each milestone requires.
  2. Audit the final product and driving question for unnecessary linguistic complexity; simplify wording while keeping the intellectual demand Clear structure supports comprehension. [+M]
  3. Plan explicit vocabulary instruction for high-utility academic terms, chunked into manageable sets introduced at point of need Chunking reduces working memory load. [+S]
  4. Design speaking/listening scaffolds for collaborative work — sentence frames, discussion roles, rehearsal time before presentations.
  5. Identify where supports will be faded as students demonstrate proficiency, so scaffolds remain temporary Fading support promotes transfer of responsibility. [+M]
  6. Build in check-ins during the project to verify that planned supports match actual learner needs.

Related Strategies¶

  • Front-loading vocabulary — the vocabulary-instruction component this analysis feeds
  • Structured collaboration — the speaking/listening scaffolds identified here get enacted there

Examples¶

  • A middle-school science PBL unit on water quality: before launch, the teacher identifies that students must explain cause-and-effect relationships in writing and negotiate findings in groups, then prepares cause-effect sentence frames and a tiered glossary (everyday → technical terms) introduced at each milestone.
  • PBLWorks (Buck Institute) guidance on ELLs in project-based learning recommends exactly this pre-launch language audit as a design step (https://www.pblworks.org).
  • A high school civics project analyzed for the language of argumentation, with claim-evidence-reasoning frames prepared before the first case-based discussion.
