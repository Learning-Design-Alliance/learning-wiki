# Support blind students' real-time code learning with flipped-classroom pacing, differentiated audio streams, and pre-course technical onboarding

> **Strategy** · [All strategies](index.md)
> **Evidence** · 2 claims (2 for) · 1 study (1 design), `q2` · 0 of 1 report an effect size · 2 claims rest on one study

## Description
This strategy responds to the two principal challenges the course revealed: real-time auditory processing load and wide variability in assistive-technology skills. The article recommends that "quality learning experiences for blind students require additional scaffolds like flipped classrooms, differentiated streams of information, and extensive onboarding to the complex technical environment." Concretely, it suggests implementing "a flipped classroom [RDM16] to support self-paced learning" since code must be listened to sequentially and individual pacing cannot be met in a live class, and rendering instructor and student screen readers in different voices or spatial locations using stereo or binaural streaming.

## Design Implications

### Context
#### Requirements
- Screen readers that can split system sounds and screen reader sounds into separate audio channels, and pre-course onboarding modules for assistive-technology skills.
#### Constraints
- Real-time classrooms cannot address individual pacing needs; the flipped-classroom approach is proposed for future implementation and was not empirically evaluated in this course.

### Target Learners
- blind and low-vision screen-reader users learning programming and data visualization online

### Target Learning Goals
- following code demonstrations without auditory overload
- self-paced mastery of nonvisual data science workflows
