# Classroom Checklists

## Description
Classroom checklists decompose a task, routine, or assignment into discrete, ordered steps that learners (or teachers) can track and mark off as completed. They externalize the plan for a task so that working memory is not consumed by remembering *what comes next*, freeing attention for *doing*. Visual design — icons, color coding, spacing — supports rapid scanning and recall.

## Design Implications

Checklists work by offloading procedural memory onto an external artifact, reducing the working-memory load of multi-step tasks [Chunking reduces working memory load.](../claims/chunking-reduces-working-memory-load.md) [+S]. Their learning value comes less from the artifact itself than from the self-monitoring behavior they prompt: checking items off requires learners to evaluate their own progress against explicit criteria, which strengthens self-regulation [Self-monitoring improves self-regulation.](../claims/self-monitoring-improves-self-regulation.md) [+M]. Framing checklist items as process goals ("I have revised my draft for clarity") rather than outcome goals ("get an A") is especially effective for novices [Process goals outperform outcome goals for novices.](../claims/process-goals-outperform-outcome-goals-for-novices.md) [+M].

### Context
#### Requirements
- A task that genuinely decomposes into discrete, observable steps — checklists fail when steps are vague or non-sequential
- Items phrased as concrete, verifiable actions rather than abstract aspirations
- A routine of use: checklists only support self-monitoring if learners actually consult them at the right moments (start, mid-point, before submission)
- Periodic revision as tasks and learners change

#### Constraints
- Overly long or dense checklists add their own cognitive load and get abandoned; each item competes for attention [~M]
- Checklists can encourage mechanical box-ticking without understanding — learners may mark items complete without doing the underlying work [~W]
- Over-reliance can prevent learners from internalizing the procedure; the checklist should be faded as routines become automatic, or it functions as a crutch [~M]
- Ineffective for open-ended, ill-structured tasks where the steps cannot be specified in advance

#### Implementation Variability
- **Student-facing task checklists** for writing, projects, or lab procedures (steps + quality criteria)
- **Routine checklists** for classroom procedures (arrival, group work transitions) aimed at automating logistics
- **Teacher-facing checklists** encoding best practices (lesson elements, differentiation moves), similar to clinical safety checklists
- **Co-created checklists**, where students help generate the items, building ownership and deeper understanding of what quality work involves

### Target Learners
- Novices and younger learners who lack internalized procedures for multi-step tasks [Process goals outperform outcome goals for novices.](../claims/process-goals-outperform-outcome-goals-for-novices.md) [+M]
- Learners with executive function or working-memory difficulties, for whom external structure is disproportionately helpful
- Less valuable for experts, who already hold the procedure in long-term memory and may find the checklist redundant or intrusive [~M]

### Target Learning Goals
- Procedural fluency: reliably executing multi-step processes without omissions
- Self-regulation: planning, monitoring, and evaluating one's own work [Self-monitoring improves self-regulation.](../claims/self-monitoring-improves-self-regulation.md) [+M]
- Organizational and study skills: managing long-horizon assignments and deadlines

### Instructions
1. Decompose the target task into 5–9 discrete, ordered steps, applying [Chunking](../principles/chunking.md) so each item is a single verifiable action
2. Apply [Clear Structure](../principles/clear-structure.md) — sequence items in execution order, group related items, and use icons or color to mark categories or priority
3. Model checklist use through [Demonstration](../elements/demonstration.md): show a learner (or yourself) working through the checklist on a real task, verbalizing each check decision
4. Introduce the checklist via [Direct Instruction](../elements/direct-instruction.md) with explicit guidance on *when* to consult it (task start, checkpoints, before submission)
5. Support [Cognitive Load Management](../principles/cognitive-load-management.md) by keeping the visible checklist short; move secondary detail to a reference page
6. Fade the checklist as learners internalize the routine, shifting from full checklists to partial prompts to independent execution

## Related Strategies
- [Activating Prior Knowledge](../strategies/activating-prior-knowledge.md) — checklists can prompt retrieval of previously learned procedures before application
- [Achievable Micro-Goals](../strategies/achievable_micro-goals.md) — checklist items function as micro-goals whose completion sustains momentum

## Examples
- **Writing-process checklists** in explicit writing frameworks (e.g., Self-Regulated Strategy Development, [SRSD](https://srsdteachers.uncg.edu/)): students check planning, drafting, and revision steps, with self-monitoring built into each stage
- **Surgical-style safety checklists adapted for classrooms**: the WHO Surgical Safety Checklist ([Pronovost-style checklist implementation](https://www.who.int/teams/integrated-health-services/patient-safety/research/safe-surgery)) inspired teacher-facing checklists for lesson routines and lab safety
- **Google Classroom / Canvas assignment checklists**: teachers publish itemized to-do lists per assignment; students check off components before submission
- **Visual routine checklists** in early-elementary classrooms using icon-based cards for arrival and transition procedures
