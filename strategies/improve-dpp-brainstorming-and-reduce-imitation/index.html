Provide more opportunities for brainstorming and discourage imitation of teacher operations in distributed pair programming¶

Strategy · All strategies
Evidence · 3 claims (3 for) · 1 study (1 causal), q3 · 0 of 1 report an effect size · 3 claims rest on one study

Description¶

Based on student feedback and the null/negative quantitative results, the authors recommend that teachers provide more opportunities for students' brainstorming, deter students from imitating teachers' programming operations, encourage idea sharing and discussion between partners, and avoid conflicts between distributed pair programming and peer-facilitated learning implementations.

Design Implications¶

Context¶

Requirements¶

  • Teachers must actively structure pair activities to promote independent idea generation rather than replication of demonstrations

Constraints¶

  • Evidence base is the study's null finding for distributed pair programming and student interviews

Target Learners¶

  • first-year undergraduate non-computer-science majors

Target Learning Goals¶

  • programming skills
  • collaborative problem-solving

Claims¶

  • The combined intervention of peer-facilitated learning and distributed pair programming does not outperform other conditions [+W]
  • Distributed pair programming significantly lowers programming skills and shows no benefit for enjoyment or intention to learn [+W]
  • Students report that distributed pair programming groups completed tasks without meaningful peer discussion [+W]

Related Strategies¶

  • Apply peer-facilitated learning in online programming courses to improve learning outcomes
