# Mandatory offline pass/fail coding exam as an artificial obstacle forcing independent programming

> **Strategy** · [All strategies](index.md)
> **Evidence** · 1 claim (1 for) · 2 studies (2 design), `q2`–`q3` · 0 of 2 report an effect size

## Description
The coding exam is the only guaranteed individual marking: students solve relatively simple programming problems on lab computers without Internet access in limited time. It is strictly pass/fail and does not affect the final grade; its purpose is to present an obstacle students cannot pass without actually learning to program. The authors are open with students that it is an artificial obstacle aimed at students who would otherwise remain in the passenger seat while more confident partners code.

## Design Implications

### Context
#### Requirements
- Lab computers with the editors, IDEs and tools used in the rest of the course, plus easily runnable test cases
#### Constraints
- Some students panic at hard error messages and get stuck on preliminaries rather than the parts the exam tests; only functional correctness determines pass/fail

### Target Learners
- second-year university programming students, especially those with low confidence in solo programming

### Target Learning Goals
- independent offline problem solving
- basic programming ability
