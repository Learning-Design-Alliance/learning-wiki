# Structure repository-metric comprehension tasks across five data aggregation levels

> **Strategy** · [All strategies](index.md)
> **Evidence** · 1 claim (1 for) · 1 study (1 causal), `q2` · 0 of 1 report an effect size · 1 claim rests on one study

## Description
The registered report plans tasks in which "Data will be visualized at multiple levels within both K IBANA and B ABIA XR: (1) project level, (2) organization level, (3) contributor level, (4) reposit ory level, and (5) subproject level". Example tasks include identifying open pull requests or issues and closing times at organizational level, and finding key contributors at project level. This provides a reusable structure for classroom exercises on process comprehension.

## Design Implications

### Context
#### Requirements
- Access to repository metrics datasets (e.g., CI/CD platform data) and a visualization tool capable of the five aggregation levels
#### Constraints
- The tasks follow the framework by Sillito et al. and the five maintenance tasks defined by Moreno-Lumbreras et al.; no evidence yet that this structure improves learning

### Target Learners
- university software engineering students

### Target Learning Goals
- analyzing repository metrics across organizational, project, and contributor scopes
