# Start an RTS in a basic form, then add CLS mechanisms only as evaluation shows necessity

> **Strategy** · [All strategies](index.md)
> **Evidence** · no claims cited

## Description
The article recommends an incremental design path for reciprocal tutoring systems: begin with the basic form that partitions a task and dispatches sub-tasks to agents without scaffolding tools, student modeling, or fading, then evaluate before enriching. The authors advise: Designers can create a RTS initially in a basic form, assess the effect of the basic form, and evaluate the necessity of adding scaffolding tools, student modeling, and fading mechanisms. After adding mechanisms, the new version must be compared to the previous version to evaluate the effect of the additions.

## Design Implications

### Context
#### Requirements
- Each added version of the RTS must be compared to the previous version to evaluate the effect of the added mechanisms
#### Constraints
- The enrichment increases complexity, which may increase student effort to engage in learning, and increases implementation costs

### Target Learners
- Students using reciprocal tutoring systems in one-to-one classrooms

### Target Learning Goals
- Learning-by-tutoring and learning-by-being-tutored
