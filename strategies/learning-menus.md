# Learning Menus

> **Strategy** · [All strategies](index.md)

## Description
A learning menu is a differentiated-instruction structure in which the teacher curates a bounded set of activity options addressing the same learning goal, and learners select which to complete. Menus vary in form: fixed menus (choose a set number), tiered menus (options at different complexity levels), and product menus (different ways to demonstrate mastery). The teacher retains control of the options; learners control the selection.

## Design Implications

Learning menus operationalize differentiation by pairing teacher-designed tasks with learner choice, which can raise motivation and engagement when the options are genuinely equivalent in value [Offering learners autonomy supports intrinsic motivation.](../claims/autonomy-supports-intrinsic-motivation.md) [+M]. The design burden sits with the teacher: every option must serve the same learning goal at comparable rigor, or the menu becomes a ranking of preferred-but-shallow tasks. Choice works best when it is meaningful (options differ in real ways) but bounded (all options are viable paths to the goal).

### Context
#### Requirements
- A single, clearly stated learning goal shared by all menu options
- Options that are genuinely equivalent in rigor and time cost — not a "hard/medium/easy" ladder that signals ability tracking
- Clear success criteria for each option, ideally via a shared [rubric](../elements/rubrics.md) so quality expectations don't vary by path
- A mechanism for accountability across different choices (e.g., [check-ins](../elements/check-in.md), conferencing, or common exit tasks)

#### Constraints
- Choice without expertise can overwhelm novices and consume working memory on decision-making rather than learning [~M] — young or novice learners may need fewer options or teacher-guided selection
- If options differ in difficulty, learners systematically choose the easiest path, undermining the goal [~M]
- Menus multiply assessment and feedback load; without manageable monitoring, off-menu or off-task work goes uncorrected [-M]
- Pure preference-based choice adds little when all options are near-identical; the motivational benefit of choice diminishes when options are trivially different [~M]

#### Implementation Variability
- **Tiered menu** — options at graduated complexity; assign the tier, let learners choose within it (mitigates easiest-path selection)
- **Product menu** — all learners do the same practice but choose the demonstration format (essay, podcast, diagram); pairs well with [authentic audiences and purposes](../principles/authentic-audiences-purposes.md)
- **2-then-1 or must-do/may-do** — a required core task plus choice among extensions; preserves coverage while adding autonomy
- **Menu boards / choice boards** — grid layouts (often 3×3, tic-tac-toe style) used in [blended learning](../patterns/blended-learning.md) and station-rotation settings

### Target Learners
- Learners with enough self-knowledge to select productively; younger learners benefit from narrower menus [Offering learners autonomy supports intrinsic motivation.](../claims/autonomy-supports-intrinsic-motivation.md) [~M]
- Mixed-readiness classrooms, where tiered options let the teacher differentiate without visible ability grouping
- Less suitable for complete novices, who lack the judgment to match options to their needs — consistent with the [expertise reversal effect](../theories/expertise-reversal-effect.md), where learner-adapted structure helps novices less as guidance is removed [~M]

### Target Learning Goals
- Consolidation and practice of already-introduced content (menus are weak vehicles for first exposure — see [Practice](../elements/practice.md))
- Application and transfer: product menus push learners to apply concepts in varied formats
- Self-regulated learning: selecting, planning, and evaluating one's own path builds [self-regulated learning](../theories/self-regulated-learning.md) habits

### Instructions
1. Define one non-negotiable learning goal and its success criteria; every menu option must map to it.
2. Design 3–6 options that vary by modality, product, or process — not by rigor. Anchor each to an element such as [Application](../elements/application.md), [Case Studies](../elements/case-studies.md), or [Argument Construction](../elements/argument-construction.md).
3. Set the selection rule (choose 2 of 5, complete the must-do then one may-do) and time frame.
4. Launch with a brief [Advance Organizer](../elements/advance-organizers.md) showing how the options connect to the goal.
5. Circulate and [check in](../elements/check-in.md) with learners across different options; hold a common debrief or exit task so all learners converge on the same understanding.
6. Debrief the choices themselves — asking learners to justify their selection builds metacognition and improves future menu use.

## Examples
- **Tiered product menu in a history unit** — all students address the same essential question; options are a written analysis, a narrated documentary segment, or a structured debate brief, each scored with the same rubric.
- **Modern Classrooms Project** ([modernclassrooms.org](https://www.modernclassrooms.org)) — blended self-paced units where learners who finish required practice choose from a menu of application tasks before mastery checks.
- **Elementary literacy "must-do/may-do" boards** — a required reading-response task followed by choice among word work, partner reading, or writing extensions during workshop time.
