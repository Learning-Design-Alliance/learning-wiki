# Keep initial TK-requirements low using block-based platforms and easily graspable simulation code

> **Strategy** · [All strategies](index.md)
> **Evidence** · 1 claim (1 for) · 1 study (1 design), `q2` · 0 of 1 report an effect size · 1 claim rests on one study

## Description
The article's second design principle advises choosing a block-based programming environment like Scratch and simulation code that is easy to grasp, so that PSTs' focus stays on the science content rather than the code. The authors observed that "when the simulation code was too complex, the PSTs mainly focused on TK-aspects while working with the code". They suggest Scratch specifically "to keep a low threshold".

## Design Implications

### Context
#### Requirements
- Simulation code that is easy for PSTs to grasp when using and modifying it, in a block-based coding environment
#### Constraints
- When the simulation code was too complex, the PSTs mainly focused on TK-aspects rather than the science content

### Target Learners
- Pre-service science teachers with little previous programming experience

### Target Learning Goals
- Technological pedagogical and content knowledge (TPACK) for programming simulations in science education
