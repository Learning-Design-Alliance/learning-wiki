# Report virtual patients by their predominant competency and technology, using class labels when they fit and explicit description when they do not

> **Strategy** · [All strategies](index.md)
> **Evidence** · 2 claims (2 for) · 1 study (1 review), `q3` · 0 of 1 report an effect size · 2 claims rest on one study

## Description
The article recommends that researchers and developers communicate the type of virtual patient they address using the adapted classification. "In case a VP does not fit into one of the classes we recommend that future researcher more explicitly explain which competency they are addressing and on which technology their VP is based on." When competency and technology are associated, the class labels from Table 1 should be used; when no suitable class exists, authors should be specific about predominant technology and competency. More detailed typologies, such as Huwendiek et al.'s for Interactive Patient Scenarios, should be used in addition whenever available.

## Design Implications

### Context
#### Requirements
- Requires reflection on the predominant competency and technology of the virtual patient before choosing a class label
#### Constraints
- The framework may need further adaptation as new innovative forms of virtual patients arise; within large classes, features and outcomes may vary significantly

### Target Learners
- healthcare education researchers
- VP developers
- educators

### Target Learning Goals
- precise communication about virtual patient types, avoiding misunderstandings between educators, researchers and IT specialists
