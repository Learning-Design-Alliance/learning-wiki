# Bounded generative AI week with documented reflection

> **Strategy** · [All strategies](index.md)
> **Evidence** · no claims cited

## Description
Rather than banning generative AI tools, the course designates one week in which students may use them under documentation requirements, treating the intervention as a bounded instructional experiment with guardrails. The article states "The course includes a designated week in which students may use generative AI if they document chat links and reflect on how the tool contributed, failed, or changed their process." Suggested activities include predicting the algorithm before prompting, interrogating model output, constructing counterexamples, and completing an oral explanation without model access.

## Design Implications

### Context
#### Requirements
- Documentation of tool use and reflection on how the tool contributed, failed, or changed the student's process; an export or instructor-provided log format is recommended over public links.
#### Constraints
- Chat-link requirements raise privacy, persistence, and platform-access issues; claims about the CP-specific implementation remain questions for direct evaluation, and the pedagogical objective is verification literacy and self-regulation, not surveillance.

### Target Learners
- undergraduate competitive programming students with access to generative AI coding tools

### Target Learning Goals
- verification literacy
- self-regulated tool use
- critical evaluation of model-generated code and explanations
