# Use blocks-based languages like App Inventor as bridging tools toward professionally relevant text-based languages, offered after a first text-based course

> **Strategy** · [All strategies](index.md)
> **Evidence** · no claims cited

## Description
The article suggests offering App Inventor-style courses at later stages of undergraduate programming education, but only for students who struggled with text-based languages, since successfully introduced students may drop in success due to adaptation problems or lack of motivation. It proposes alleviating the motivation problem by using simpler blocks-based languages "as bridging tools for passing over to the more advanced and professionally relevant text -based languages", consistent with an App Inventor–Java hybrid model it cites.

## Design Implications

### Context
#### Requirements
- Placement after an initial conventional text-based programming course
- Framing the visual tool as a bridge to an industrially relevant text-based language
#### Constraints
- May cause a drop in success for students already successfully introduced via text-based languages; employing such tools de facto accepts a GUI-first paradigm and should be an informed decision

### Target Learners
- undergraduate prospective K12 ICT teachers
- novice programmers who struggled with text-based languages

### Target Learning Goals
- GUI-programming concepts
- object-orientation concepts
- motivation for programming
