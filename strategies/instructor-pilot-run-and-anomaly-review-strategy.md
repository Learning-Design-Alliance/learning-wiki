# Instructor pre-tests the workflow and designates student anomalies as scientifically interesting starting points

> **Strategy** · [All strategies](index.md)
> **Evidence** · no claims cited

## Description
The strategy is for the instructor or research group to "run one or more examples in detail to verify the workflow and be aware of potential problems" before class. During analysis, students are told to "keep a close eye out for any anomalies in the data, which can be real physically interesting phenomena, artefacts due to sophisticated computational problems, or the result of trivial cut-and-paste mistakes", and students should identify and fix anomalies themselves. Students also submit raw input and output to a shared folder so calculations can be audited.

## Design Implications

### Context
#### Requirements
- A shared repository (e.g. a common spreadsheet) for key results and a shared folder for raw input/output
- A carefully defined protocol so results constitute a set of comparable class data
#### Constraints
- "the only way to completely exclude such problems is to do all the students' calculations beforehand, which defeats the purpose of a CURE"

### Target Learners
- undergraduate and graduate students performing research calculations

### Target Learning Goals
- data quality awareness and error tracing
- scientific judgment about anomalous results
