# Teach computation via guided lab-built programs that students independently alter to solve modified homework problems, checked against a provided test case before a graded case.

> **Strategy** · [All strategies](index.md)
> **Evidence** · 4 claims (4 for) · 2 studies (2 design), `q2`–`q3` · 0 of 2 report an effect size · 2 claims rest on one study

## Description
The implementation philosophy held that students learn computation by writing a program in a TA-guided laboratory, then altering their own lab-developed program on homework to solve a modified problem, mirroring how research scientists reuse code. Each assignment embedded a test case with a given solution that students checked their program against before solving the grading case, which helped students debug and instilled confidence. Eleven of thirteen labs contained computational activities, with one computational homework problem per week.

## Design Implications

### Context
#### Requirements
- Deployable across large lecture sections without assuming prior programming experience
- A lab environment where TAs can check students' completed code before independent homework
#### Constraints
- Weekly online grading covered only final results; grading code for structure and syntax at scale would require additional TA work

### Target Learners
- introductory calculus-based mechanics students, roughly half with no programming experience

### Target Learning Goals
- using Newton's second law iteratively to predict the motion of physical systems with computation
