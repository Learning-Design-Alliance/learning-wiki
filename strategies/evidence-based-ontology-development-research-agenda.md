# Advance ontology development as an evidence-based engineering activity: validate quality parameters empirically, build an easy-to-use metrics toolbox, and change developer behaviour incrementally

> **Strategy** · [All strategies](index.md)
> **Evidence** · 5 claims (1 for, 2 mixed, 2 against) · 1 study (1 causal), `q1` · 0 of 1 report an effect size · 5 claims rest on one study

## Description
The article's forward-looking recommendations call for ontology development to be led by a high level of evidence rather than only expert opinion, in analogy to evidence-based medicine. Concretely, it recommends developing evaluation methods that quantify quality parameters for a specific description logic expressivity regime and validating them empirically, possibly via competency questions formalized as logical expressions; providing an easy-to-use toolbox of ontology metrics applicable from the ontology editor so developers can evaluate artefacts at each step; and investigating how to change the thinking, behaviour, communication and tools of the developer community through educational studies that change only one parameter at a time.

## Design Implications

### Context
#### Requirements
- Quality indicators should be unambiguous and measurable in a reproducible way, ideally automatically to avoid any bias
#### Constraints
- The article notes many open questions remain on how to measure quality indicators of ontologies technically, reproducibly and automatically

### Target Learners
- ontology developers and the community of ontology developers

### Target Learning Goals
- adopting evidence-based good practices in ontology design and development
