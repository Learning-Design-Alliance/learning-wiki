# Hand out purposely broken code samples for learners to fix or improve

> **Strategy** · [All strategies](index.md)
> **Evidence** · 1 claim (1 for) · 1 study (1 qualitative), `q2` · 0 of 1 report an effect size · 1 claim rests on one study

## Description
As a pedagogical technique for computing training, the paper suggests that "it may even be advantageous to hand out code samples that are purposely broken or ﬂawed, and ask students to ﬁx or improve them." This active-repair activity is offered alongside active learning, peer learning and web-based training as approaches any training programme should take advantage of where possible. The paper acknowledges that learning material in a way that sticks is difficult and often takes more time than preferred.

## Design Implications

### Context
#### Requirements
- Instructors willing to prepare flawed sample code and guide students through repair activities
#### Constraints
- The paper notes this style of learning "often takes more time than we would prefer" for both students and instructors

### Target Learners
- HEP trainees across experience levels learning programming concepts

### Target Learning Goals
- Programming concepts, debugging, and code improvement skills
