# Scaffold computational activities from built-in functions toward student-written code within a physics course

> **Strategy** · [All strategies](index.md)
> **Evidence** · 2 claims (2 mixed) · 2 studies (2 qualitative), `q2` · 0 of 2 report an effect size · 2 claims rest on one study

## Description
The professor deliberately sequenced computational work so students first used built-in MATLAB functions for linear fitting and later wrote their own fit functions, aiming to have students "use the canned programs to begin with so they can just see how it works" before combining code with statistics. Homework assignments explicitly told students their code was directly applicable to labs, and every lab analysis required MATLAB, so computation was repeatedly practiced in physics contexts rather than taught as a stand-alone skill.

## Design Implications

### Context
#### Requirements
- Course structure with recurring homework and lab components that reuse the same computational techniques
#### Constraints
- The professor felt constrained by having only one lecture per week and could not also teach MATLAB directly

### Target Learners
- sophomore-level undergraduate physics students

### Target Learning Goals
- using computation as a tool to learn physics
- comfort with a computational platform
