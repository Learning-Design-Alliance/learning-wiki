# Sort And Classify

> **Strategy** · [All strategies](index.md)

## Description
Sort and classify asks learners to organize a set of items — examples, objects, statements, problems — into groups according to features or rules. The activity can be *closed* (a known taxonomy to be applied) or *open* (learners induce the categories themselves), and the sorting process, including discussion of why items belong together, is the learning mechanism.

## Design Implications

Sorting forces comparison: to decide whether two items belong together, learners must attend to features, which supports discrimination and category formation [Comparing and contrasting cases improves learning.](../claims/comparing-contrasting-cases-improves-learning.md) [+S]. Open sorts in which learners generate their own categories produce deeper processing than applying a given scheme, but closed sorts are more effective for novices who lack the knowledge to induce categories on their own [~M]. Grouping items also chunks material into meaningful structures, easing working-memory load [Chunking reduces working memory load.](../claims/chunking-reduces-working-memory-load.md) [+M].

### Context
#### Requirements
- A carefully chosen item set with meaningful similarities and differences; distractors should differ on relevant dimensions, not just surface features
- A clear sorting criterion — either a target taxonomy or an expectation that learners justify self-generated categories
- A debrief in which learners articulate their rules and compare them against expert classification ([Discussion](../elements/discussion.md) or instructor feedback)

#### Constraints
- With poorly chosen item sets, learners sort on surface features and miss the deep structure [-M] — items must vary systematically on the dimensions that matter
- Open sorting overwhelms novices who lack schemas for generating categories [-M]; provide the taxonomy first and fade toward open sorts
- Sorting without explanation or feedback can leave misconceptions uncorrected, since any grouping "works" if the learner can justify it [-W]

#### Implementation Variability
- **Card sorts** — physical or digital cards moved into groups; fast, manipulable, easy to re-sort
- **Concept attainment** — instructor sorts exemplars and non-exemplars; learners infer the rule
- **Problem classification** — learners sort problems by which solution strategy applies, a known precursor to successful problem solving
- **Progressive sorting** — begin with two categories, add dimensions and categories as expertise grows

### Target Learners
- Novices building initial categories in a domain; closed sorts with feedback work best [~M]
- Learners who tend to memorize lists rather than structure; sorting imposes relational processing [+M]
- Advanced learners benefit more from open sorts and re-sorting the same items under different criteria [~W]

### Target Learning Goals
- Concept formation and discrimination: learning what makes items same or different
- Structural knowledge: seeing how a domain is organized taxonomically
- Conditional knowledge: knowing which strategy or rule applies to which case

### Instructions
1. Select 8–20 items that vary on the target dimensions and include borderline cases that provoke discussion.
2. Present the task: apply a given taxonomy, or induce categories and name them.
3. Have learners sort, individually or in pairs, and record the rule behind each group.
4. Debrief: compare groupings, surface surface-feature errors, and state the expert classification with reasons.
5. Re-sort under a second criterion to show that classification depends on purpose.

## Examples
- **CGI math classrooms** — students sort word problems by whether the unknown is a result, change, or start quantity, building the problem-type schemas underlying [Cognitively Guided Instruction](../patterns/cognitively-guided-instruction-cgi-for-math.md).
- **Biology card sorts** — learners sort organism cards into phyla, then re-sort by reproductive strategy, showing that valid classifications depend on the question asked.
- **Programming courses** — students sort short code snippets by which data structure or algorithm each requires, before writing any code themselves.
