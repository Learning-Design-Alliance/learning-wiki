# Grade programming assignments by peer assessment plus automated unit testing to learn from peers and scale the course

> **Strategy** · [All strategies](index.md)
> **Evidence** · 1 claim (1 for) · 1 study (1 causal), `q2` · 0 of 1 report an effect size · 1 claim rests on one study

## Description
The course combined two grading channels for online programming assignments: "programming assignments were graded by peers for sixty percent of the assignment grade; and for the remaining forty percent they were graded automatically, except for some problems that were not amenable to unit testing." At least four students were assigned to evaluate each assignment using a rubric covering aspects such as correctness and readability. The authors believe there are "significant benefits to peer assessments, as students can learn from seeing various approaches to the same problem," and that this combination allows the course "to easily be scaled up."

## Design Implications

### Context
#### Requirements
- A grading rubric detailing point allocation across aspects such as correctness and readability
- Template code structured around unit-testable functions so most problems can be autograded
- Assignment of at least four peer evaluators per student's work
#### Constraints
- Some problems, notably a few visualization problems, are not amenable to unit testing and were not autograded

### Target Learners
- Online students without prior programming experience in large or scalable course offerings

### Target Learning Goals
- Programming practice; judging correctness and readability of code; learning from alternative solution approaches
