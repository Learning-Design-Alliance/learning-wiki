# Improve hands-on quantum courses with live system status, simpler access, better job management, and richer documentation

> **Strategy** · [All strategies](index.md)
> **Evidence** · 3 claims (3 for) · 1 study (1 design), `q2` · 0 of 1 report an effect size · 3 claims rest on one study

## Description
From the first course deployment the authors distil improvements for hands-on quantum education: up-to-date calibration data and clear system workload indications, smoother HPC-QC access procedures, job-management features such as returning a queue object and viewing queued jobs, resolving missing or conflicting software packages, more quantum providers, flexible scripting support, and richer MQP dashboard information. Future iterations 'will prioritize improvements to documentation, user accessibility, resource integration, and system information/status'.

## Design Implications

### Context
#### Requirements
- Responsive infrastructure and tools, supported by ongoing Munich Quantum Valley projects and MQSS development
#### Constraints
- Slow remote access can cause confusing experiences for experiments with short execution times but a large number of jobs

### Target Learners
- students in hands-on quantum computing lab courses

### Target Learning Goals
- effective experimentation and performance analysis on shared quantum systems
