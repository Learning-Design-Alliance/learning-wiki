# Coding-focused GenAI declaration structure with five activity categories

> **Design** · [All designs](index.md)
> **Evidence** · no claims cited

## Description
A parallel declaration structure for coding assessments reflecting typical phases of software development and code-based learning, with five activity categories: Planning & Design, Code Generation, Code Improvement, Understanding & Learning, and Documentation & Reporting. As in the writing structure, students indicate whether GenAI was used and to what extent, with a short description and example prompts. The structure lets students and instructors "distinguish between GenAI as a learning aid (e.g., understanding error messages) and GenAI as an authoring tool (e.g., generating core solution code)".

## Design Implications

### Context
#### Requirements
- Students complete per-category use, extent, and description fields; institutional guidance on tool scope is recommended by the authors
#### Constraints
- Derived from a computing-education taxonomy; relies on accurate self-reporting in a context where students may misattribute GenAI contributions

### Target Learners
- Computer Science students in programming-based assessments, from novices learning Python syntax to degree apprentices debugging legacy codebases

### Learning Goals
- Transparent disclosure of GenAI use in coding tasks
- Distinguishing GenAI as learning aid versus authoring tool
