# Open-ended lab design with loosely specified guidelines, student-built apparatus, and rotating group roles

> **Design** · [All designs](index.md)
> **Evidence** · 2 claims (2 for) · 1 study (1 causal), `q2` · 0 of 1 report an effect size · 2 claims rest on one study

## Description
This pattern organises an undergraduate physics lab around student decision-making: students design their own apparatus from Arduino and smartphone components, decide measurement strategies, and edit both data-acquisition and analysis code. Pre-session documents give "general guidelines about each lab activity" and were "designed so as not to specify too many details, not following a step -by-step recipe format , leaving room for student creativity and initiative". Groups of three or four students are formed without self-selection, and role rotation per session is recommended so each member takes on different roles.

## Design Implications

### Context
#### Requirements
- Students need prior programming experience; a prior C programming course meant a two-hour session sufficed for Arduino-specific statements.
- Each group should rotate roles for each experimental session so every member takes on different roles.
#### Constraints
- Students purchase their own affordable kit (Arduino UNO, breadboard, cables, ultrasonic and temperature sensor).
- Spontaneous group formation was not allowed, which per student feedback produced imbalanced groups perceived as detrimental, especially by female students.

### Target Learners
- first-year undergraduate physics students

### Learning Goals
- designing experimental apparatus and measurement strategies
- data analysis with Python and Bayesian reasoning
- teamwork and communication in lab groups
