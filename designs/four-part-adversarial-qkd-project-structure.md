# Four-part adversarial QKD project structure progressing from ideal to practical to adversarial

> **Design** · [All designs](index.md)
> **Evidence** · no claims cited

## Description
A reusable project sequence: individual ideal implementation, group implementation with nonidealities, adversarial Eve development against an anonymous peer group, and a mini-symposium presentation. Each group's Alice-and-Bob protocol "is anonymized and given to another, random group to act as an attacking eavesdropper, Eve." Presentations use a mini-symposium format with a one-minute Q&A that encourages peer engagement.

## Design Implications

### Context
#### Requirements
- Groups must not complete their Eve code while developing Alice and Bob; the final code should have Eve removed
#### Constraints
- Prior introduction to QKD and the BB84 protocol is needed; the practical part prioritizes clarity of code over efficiency

### Target Learners
- high school students
- first-year undergraduates

### Learning Goals
- understand practical QKD including security checking and eavesdropping detection
- develop programming, teamwork, and presentation skills
