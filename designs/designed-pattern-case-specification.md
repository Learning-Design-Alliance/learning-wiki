# Designed-pattern authoring: linking each teaching pattern to its generation rule, check, and reference analysis

> **Design** · [All designs](index.md)
> **Evidence** · no claims cited

## Description
A designed pattern is "a trend, group difference, interaction, or exception intentionally built into a dataset for students to investigate." The workflow records each pattern in an executable case specification connecting it to its generation rule, comparison groups, measurement, and sample-size requirements, so that the generation rule, numerical check, reference chart, and rubric use the same definition of the intended finding. Verification examines the combined effect of interacting rules on the exported data, and the probability set in the generator is not itself evidence that the pattern appears in the data.

## Design Implications

### Context
#### Requirements
- Each pattern requires one or more checks; the specification defines how overlapping rules interact, since an adjustment made for one pattern may affect another
#### Constraints
- The order of generation rules affects what students observe; in WindowDash the ZIP 10011 cuisine adjustment overrides earlier cuisine rules

### Target Learners
- undergraduate business analytics students

### Learning Goals
- investigating unfamiliar data with AI
- distinguishing counts from shares
- justifying conclusions from evidence
